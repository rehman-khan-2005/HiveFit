## What was done

See [timeline v0.4](../timeline.md#v04--12-november-2026--23-november-2026).

**Bands set to 80 / 60 / 40**, each shipping an interpretation and an
instruction, with the whole ladder shown on the analysis screen and the user's
own band highlighted.

**Boards called only on intent.** Opening the tab went from three provider
requests to none — 77 ms from the stored pool, against 1418 ms when the user
presses Refresh. Expiry also moved off the read path, where it had been
shrinking the pool for someone who was only scrolling.

**The SpaceX 80.** Explained rather than fixed: that posting is short, so it
scores like the purpose-written reference ladder rather than like a typical
real listing. This turned out to be the thread that led to
[the scoring ceiling finding](../findings/scoring-ceiling.md).

## Flagged at this meeting, unresolved

Setting the bands prompted a check against real listings rather than the
purpose-written ladder, and **98% of live postings landed in the bottom band**.
This was documented rather than quietly patched, with the proposed fix — score
against the terms a posting leans on — deferred to the next meeting, because it
would change every score the report cites.

The 23 November meeting then asked for a 50% cutoff, which forced the issue.
The proposed fix was implemented, measured, and found not to work; see
[findings/scoring-ceiling.md](../findings/scoring-ceiling.md) for what happened
instead.
